## Demo Site Now Supports Docker

Since we last used our Jekyll demo site, [Helma Van Der Linden](https://github.com/hepabolu) was kind enough to contribute [Tidbit 17](./tidbit17), teaching us all how to use [Docker](https://www.docker.com) to simply our development environment.

Since learning this very useful skill from Helma, I've been doing all my Jekyll development work using Docker, and just like Helma promised, it really does make life a lot easier!

I've taken Helma's worked example from the tidbit, which was a Docker setup for deploying Jekyll, and merged it into the demo site. I'm now using this approach for working on this series.

If you'd also like to switch from a single locally installed instance of Jekyll to per-site installed handled by Docker, please do the following:

1. Listen to and/or read through the notes for [Tidbit 17](./tidbit17)
2. Install Docker
3. Download or clone any version of the `pbs-jekyll-demoSite` repo after the commit tagged `docker` [from GitHub](https://github.com/bartificer/pbs-jekyll-demoSite)
4. Open a terminal in the downloaded/cloned folder and execute the command `make install` to initialise the Docker image

Once that has been done, you can start and stop the Docker container hosting the demo site with the commands `make up` and `make down`, and you can see the Jekyll logs with the command `make logs`.

## PBS 181 Challenge Solution

Before we took our break from the Jekyll mini-series, way back in [instalment 181](./pbs181), we ended with a challenge.

As a reminder, we have been using a separate [GitHub repository](https://github.com/bartificer/pbs-jekyll-demoSite) to track the demo Jekyll site we're building throughout the series. Each important point in our journey has been marked with a tagged commit, so you can download the code at the relevant point in the series from [the repo's tag listing](https://github.com/bartificer/pbs-jekyll-demoSite/tags), or fork the repo, clone it to you own device, and check out the relevant tagged commits as needed.

As with the previous instalments in this mini-series, the starting point for the challenge is a tagged commit on [the demo site repo](https://github.com/bartificer/pbs-jekyll-demoSite), specifically [pbs181-challenge-startingPoint](https://github.com/bartificer/pbs-jekyll-demoSite/releases/tag/pbs181-challenge-startingPoint). To play along you can download it from GitHub as a ZIP file and extract it, or, you can fork the repo, clone it, and check out the relevantly tagged commit.

In [PBS 181](https://pbs.bartificer.net/pbs181) we learned to create re-usable snippets that can act as template-like additions to the regular markdown in our content files. The challenge was to create such a re-usable snippet for adding side-notes to our content. There were just three criteria:

1. The snippet needs to receive its contents as an argument named `content`.
2. Markdown within note contents should be correctly handled
3. The note should be rendered using a [Bootstrap 5 card](https://getbootstrap.com/docs/5.3/components/card/).

To get a very basic working solution, create a file named `./docs/_includes/notes.html` and add the following content

```html
{%raw %}<div class="card text-bg-light">
  <div class="card-body">
    <div class="card-text">{{ include.content | markdownify }}</div>
  </div>
</div>{% endraw %}
```

This is all we need to define a re-usable snippet that adds a basic Boostrap card with one placeholder named `content`.

As a refresher, Jekyll's term for re-usable snippets is *includes*, and within an include you access the values passed to the snippet by prefixing argument names with `include.`, so the argument named `content` is available as `include.content`.

Because our snippet needs to render markdown correctly, we need to pipe the value we receive through Jekyll's `markdownify` Liquid filter.

To to use the new snippet, add the following to the end of `index.md` (leaving a blank line above it):

```
{% raw %}{% include note.html content="This site has no *useful* content, it's all just filler!" %}{% endraw %}
```

Allow the site to re-build, and you should see the note appear under the front page's content. Notice that the word *useful* is in italics, proving markdown rendering is working as expected.

That's it — that's all we needed to do for full credit!

But there was some bonus credit on offer, so let's try earn that 🙂

The first bonus challenge was add an optional title to the card. To do that we'll use a new argument named `title` which we'll need to treat as optional. That means we need to add a conditional section to our card. Update your `note.html` file to the following:

```html
{% raw %}<div class="card text-bg-light">
  {%- if include.title %}
  <div class="card-header">
    {{ include.title }}
  </div>
  {%- endif %}
  <div class="card-body">
    <div class="card-text">{{ include.content | markdownify }}</div>
  </div>
</div>{% endraw %}
```

By wrapping our header inside `{% raw %}{% if %}…{% if %}{% endraw %}` Liquid tags we ensure it only appears when a title is actually specified.

Before adding a title, let the site re-build and verity that the note remains un-changed.

Now, to add a title, edit the `{% raw %}{% include %}{% endraw %}` statement in  `index.md` to become:

```
{% raw %}{% include note.html title="Note" content="This site has no *useful* content, it's all just filler!" %}{% endraw %}
```

Allow the page to re-build, and notice that our note now has a title telling us it's a note.

The final extra challenge is to add an optional link for more information.

This doesn't introduce any new concepts, it just involves applying the same principle again. Update your `note.html` to the following:

```html
{% raw %}<div class="card text-bg-light">
  {%- if include.title %}
  <div class="card-header">
    {{ include.title }}
  </div>
  {%- endif %}
  <div class="card-body">
    <div class="card-text">{{ include.content | markdownify }}</div>
  </div>
  {%- if include.info_url %}
  <div class="card-footer text-end">
    <a href="{{ include.info_url }}" class="card-link" target="_blank">more …</a>
  </div>
  {%- endif %}
</div>{% endraw %}
```

Now, to add a title, edit the `{% raw %}{% include %}{% endraw %}` statement in  `index.md` to become:

```
{% raw %}{% include note.html title="Note" content="This site has no *useful* content, it's all just filler!" info_url="https://typography.guru/video/the-unsolved-mystery-of-lorem-ipsum-r151/" %}{% endraw %}
```

Allow the page to regenerate, and notice that there's now a footer on the note with a link for more information.

The demo site with the completed solution merged in is available via the tagged comment [pbs181-challenge-solution](https://github.com/bartificer/pbs-jekyll-demoSite/releases/tag/pbs181-challenge-solution)
