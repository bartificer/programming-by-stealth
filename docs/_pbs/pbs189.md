At this point in our journey we know Jekyll has three top-level taxonomies — *pages*, *posts*, and *collections*. We've been using *pages* for our entire exploration of Jekyll, and in the previous instalment we explored how *posts* can be used to add a blog or new feed to a Jekyll site. That leave just one unexplored taxonomy — *collections*. This is Jekyll's general purpose taxonomy, and it's used to add any organised content that is not a page or a post. Because you can add what ever custom attributes you like, you can use collections to represent just about anything.

The possible uses of collections are countless and infinite, so this instalment will be an overview of the concepts rather than a complete review of everything that's possible.

## Two Kinds of Collections

Collections come in two flavours, those that are rendered, and those that aren't. By default, when you create a collection it is not rendered. That means that when you add an item to the collection **it does not get its own page**. These un-rendered collections are intended to be used within other parts of the site.

An example might be a collection of social media profiles that get included on every page.

When you define a collection you can choose to have it rendered by setting the collection's `rendered` property to `true`. These kinds of collections behave like *pages* and *posts*, each new item gets a dedicated page in your generated website. These can be used for things like profile pages, conference talks, recipes, or any other item that's not a regular page or a blog post.
